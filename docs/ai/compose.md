# Compose: готовые элементы

Что уже написано на Compose. Перед новым UI на Compose — проверить здесь, нет ли подходящего элемента: переиспользовать или расширить его, а не писать однотипный.

## Правила

- **Общие элементы** (нужны или могут понадобиться больше чем одному экрану) — в `ui/compose/`, пакет `me.zhanghai.android.files.ui.compose`, имя с префиксом `Mftlrs`. Тема — в `ui/theme/`.
- **Элементы одного экрана** — в папке `ui/` экрана (`filelist/ui/` и т. п.), `private`, если не нужны снаружи; ViewModel и её состояние — уровнем выше (`filelist/`), данные экрана — в `data/`. Понадобились второму экрану — вынести в `ui/compose/`, а не копировать.
- Каждый новый, вынесенный или удалённый элемент — сразу отметить в таблице ниже.
- Цвета — только из `MaterialTheme.colorScheme` (палитра `MftlrsTheme`), строки — из ресурсов.

## Экран целиком на Compose

Образец — `FileListActivity` (без фрагментов и View):

- `setContent` из `activity-compose` (на `AppCompatActivity` тоже) сам ставит владельцев `ViewTree*` на decor view; `viewModel()` внутри берёт хранилище Activity;
- «Назад» — `BackHandler`, все в одном месте в нужном порядке, условия — через `enabled` (`FileListRoot`): появившийся по условию `BackHandler` встаёт в начало очереди;
- лаунчеры `ActivityResult` — `registerForActivityResult` в Activity при создании (`FileListPermissions`), разовые события ViewModel собирает Activity в `repeatOnLifecycle(STARTED)`;
- отступы под системные панели — слушатель на `android.R.id.content`, не на `ComposeView` ([gotchas.md](gotchas.md), «Отступы под системные панели»).

## Compose внутри экрана на Views

Для остальных экранов, пока они на Views:

- если у Activity нет `setContentView`, у decor view нет владельцев `ViewTree*`: `ComposeView` надо дать их вручную (`setViewTreeLifecycleOwner`, `setViewTreeSavedStateRegistryOwner`), иначе падение при attach; внутри view фрагмента `ComposeView` находит их сам;
- стратегия — `ViewCompositionStrategy.DisposeOnViewTreeLifecycleDestroyed`;
- для элементов в своём окне (`Dialog`, `MftlrsBottomSheet`) `ComposeView` может быть размера 0 в `android.R.id.content`;
- `ComposeView` поверх других View пропускает касания туда, где нет Compose-элементов с обработкой касаний: View под ним работают. Внутри одного `ComposeView` так же: пустое место слоя FAB не мешает списку;
- атрибуты тем Views (`?colorControlNormal`, `?textAppearanceListItem` и др.) в Compose заменять значениями `MaterialTheme`, подбирая так, чтобы цвет и размер совпали.
